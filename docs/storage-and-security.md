# Local storage and services

The local broker binds `127.0.0.1:4269`. Development uses a loopback Vite server on port 3000 with an API proxy. Set `VOXSHOP_CLIENT_PORT` to select another free editor port; Vite and the broker use the same exact port for their Origin allowlist, and Vite refuses silent port fallback. Production serves the built editor from the broker. A random session capability protects API requests; browsers must also satisfy an exact Origin/Host check. MCP reads the capability from the local workspace and sends it in a header, never a URL.

These controls protect against ordinary cross-site requests and DNS rebinding. They are not an operating-system sandbox against another process running as the same user. Keep the workspace directory private. Do not expose this service through a public tunnel or reverse proxy.

## Workspace files

| Location                                 | Purpose                                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| `.voxshop/projects/<id>.json`            | Current validated project, bounded undo/redo history and recent retry receipts |
| `.voxshop/projects/<id>.json.bak`        | Previous committed save                                                        |
| `.voxshop/projects/<id>.json.replaced-*` | Preserved file from an explicit recovery operation                             |
| `.voxshop/workspace.json`                | Active project selection                                                       |
| `.voxshop/access.json`                   | Local service address and session capability; do not share                     |
| `.voxshop/broker.lock`                   | Single-writer broker lock; stale dead-process locks are recovered              |
| `.voxshop/exports/`                      | Portable project snapshots requested through MCP                               |
| `.voxshop/games/`                        | Independent HTML game builds                                                   |
| `.voxshop/presets/`                      | User-created workshop presets                                                  |
| `.voxshop/bridge/<requestId>/`           | Isolated optional compatibility-worker request, response and status            |

`.voxshop` is Git-ignored. Set `VOXSHOP_DATA_DIR` to select a different private workspace, and `VOXSHOP_ROOT` when launching built server/MCP files from another working directory. Only one broker may own a workspace. The MCP configuration generated by the editor includes its actual paths and data directory.

Local Sites preview account/project bindings live in `.openai/hosting*.json`. They are ignored by Git and excluded from the source manifest and archive because they identify private hosting projects and are not needed by the engine.

Project commits use a temporary file, file sync and atomic rename. A previous-save backup is kept before replacement. Imports validate before writing and allocate a fresh project ID. Recovery preserves the replaced file and advances the revision so stale clients cannot silently overwrite recovered work. This protects individual saves; it is not a substitute for independent backups or protection from disk failure.

The browser's `voxshop-recovery` IndexedDB database keeps the latest unsent sculpt draft per project, along with its asset ID and base revision. Failed or conflicting saves leave it available as a separate recovered asset. Clearing browser data also clears this recovery copy. Project files on disk remain separate.

## AI and networking

Built-in generation, authoring and exported gameplay do not require an AI provider. Optional AI generation sends the prompt and any requested current-grid context to the endpoint the creator selected. The key remains in memory for the current editor session. It is not included in project files, game builds or server diagnostics. Existing saved settings are rewritten without the key when the sculpt editor opens.

The proxy permits exact provider origins from `VOXSHOP_AI_ORIGINS`, rejects credentials in endpoint URLs and redirects, limits responses to 20 MiB, and times out after two minutes. Defaults include OpenAI, Google's OpenAI-compatible endpoint, and loopback Ollama/LM Studio ports. Add another trusted origin explicitly at service startup; this is not an unrestricted URL fetcher.

The compatibility worker is optional. Each request has a private request directory and response ID. A disconnect/cancel marks that attempt cancelled; a late response does not apply to a different project. Finished request files remain locally available for diagnosis until the owner removes them. A worker must write `{requestId, voxels}` atomically, not the old shared `_bridge/response.json` array.

Generation, test and build job status is held in memory and bounded. A broker restart loses job-status records; inspect the saved project revision or existing artifact before retrying. Generation transactions retain retry receipts for the most recent 128 requests. A cancellation after a transaction has already committed does not reverse it; use project undo.

The editor has no telemetry upload and no external font dependency. Diagnostics are bounded local records of IDs, status and events. A compatible external agent receives project data through its tool calls and has its own data handling. Self-contained exports embed reachable campaign scenes and referenced assets. Their content policy allows optional secure or loopback multiplayer connections; games do not contact an AI service. Joining a multiplayer room sends gameplay state to the chosen host.

## Release privacy

User projects, access tokens, local account bindings, logs and acceptance recordings are excluded from published release contents. Windows builds remap local compiler paths. The installed editor carries its runtime, public agent guidance and required license notices; developer tests and execution notes are not application resources.

Local service access is not an OS sandbox. A process already running as the same user may read that user's project files. Use trusted agent clients and model endpoints, keep access files private, and report suspected security problems without posting real credentials or private projects in public issues. Dependency audits and regression checks reduce known risks; they do not guarantee an absence of vulnerabilities.
